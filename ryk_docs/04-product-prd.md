# Product Requirements Document

## 1. Product Summary

Ryk — мобильный AI-компаньон, который каждую неделю помогает пользователю выбрать, организовать, прожить и сохранить одно значимое впечатление.

## 2. Цели продукта

1. Увеличить количество реально прожитых впечатлений.
2. Снизить разрыв между «хочу» и «сделал».
3. Создать устойчивый еженедельный ритуал.
4. Построить персональную модель интересов и жизненного баланса.
5. Сформировать эмоционально ценный архив жизни.

## 3. Не-цели первой версии

- Полноценная социальная сеть.
- Открытый marketplace для всех организаторов.
- Терапевтическое или медицинское сопровождение.
- Универсальный календарь и task manager.
- Автоматическое бронирование без подтверждения пользователя.

## 4. Основные сущности

### User Profile

Интересы, предпочтения, ограничения, бюджет, расписание, социальный стиль, история обратной связи.

### Wish

Желание, созданное пользователем или принятое из рекомендации.

### Experience

Конкретный реализуемый сценарий с датой, местом, стоимостью, подготовкой и уровнем вызова.

### Weekly Story

Выбранное впечатление недели, вокруг которого строится сопровождение.

### Memory

Завершённая история: фото, заметка, эмоция, участники, место, дата и обратная связь.

### Companion Intervention

Сообщение или действие AI, помогающее пользователю двигаться к выполнению.

## 5. Основные модули

### 5.1 Онбординг

Собирает минимум данных, достаточный для первых полезных рекомендаций.

Обязательные блоки:

- категории интересов;
- нравится/не нравится через свайпы;
- допустимый бюджет;
- доступное время;
- предпочтение «один / с близкими / с новыми людьми»;
- география и радиус;
- уровень спонтанности;
- желаемая доля нового и комфортного.

### 5.2 Wishlist

Пользователь может:

- написать желание своими словами;
- сохранить рекомендацию;
- импортировать ссылку;
- указать сезон, цену, компанию и приоритет;
- временно скрыть идею;
- отметить «когда-нибудь», «в этом месяце», «скоро».

### 5.3 Weekly Selection

Раз в неделю приложение формирует 3–5 кандидатов:

- одно желание пользователя;
- одна своевременная локальная возможность;
- одно маленькое и лёгкое впечатление;
- один вариант с лёгким выходом из зоны комфорта;
- опционально совместный сценарий.

Пользователь выбирает сам или включает режим «выбери за меня».

### 5.4 Commitment

После выбора пользователь подтверждает:

- ориентировочный день;
- бюджет;
- формат компании;
- желаемый уровень поддержки;
- кому можно сообщить о намерении.

### 5.5 Planning Assistance

Продукт помогает:

- подобрать время;
- показать погоду;
- найти билет или бронь;
- построить маршрут;
- подготовить список вещей;
- составить сообщение другу;
- предложить запасной вариант.

### 5.6 Companion Nudges

AI должен реагировать на контекст, а не отправлять фиксированные напоминания.

Примеры:

- «В субботу дождь, но воскресенье отлично подходит для похода».
- «Билеты почти закончились. Забронировать сейчас или выбрать другой концерт?»
- «Похоже, идти одному не хочется. Кого из близких можно позвать?»
- «На большую поездку не хватает сил. Давай спасём неделю короткой прогулкой и новым местом?»

### 5.7 Rescue Mission

Если основной план срывается, пользователь получает 2–3 альтернативы меньшего масштаба, соответствующие исходной потребности.

Пример: поход отменился из-за погоды → ботанический сад, скалодром или прогулка по новому району.

### 5.8 Completion and Memory

После события пользователь отвечает максимум на три вопроса:

1. Получилось?
2. Какое чувство осталось?
3. Хочешь добавить фото или одну фразу?

Memory автоматически сохраняет контекст события.

### 5.9 Timeline

Архив должен показывать:

- истории по неделям;
- карту мест;
- людей, с которыми пользователь проводил время;
- баланс категорий;
- подборки «лучшее за год»;
- незавершённые желания без чувства вины.

## 6. Life Balance Model

Категории:

- Joy — простая радость;
- Connection — люди и близость;
- Discovery — новое;
- Movement — тело и активность;
- Culture — искусство и знания;
- Nature — природа;
- Challenge — маленький вызов;
- Rest — восстановление;
- Contribution — помощь и вклад.

Система не должна навязывать идеальный баланс. Она только замечает перекосы и предлагает мягкие варианты.

## 7. Functional Requirements

- Пользователь может завершить онбординг менее чем за 5 минут.
- Первая полезная рекомендация появляется сразу после онбординга.
- Weekly Story выбирается максимум за 60 секунд.
- Пользователь может изменить или отменить историю без штрафа.
- Для каждого предложения объясняется «почему это подходит».
- Спонсорские предложения явно маркируются.
- Любые покупки требуют явного подтверждения.
- Пользователь может управлять уровнем уведомлений.

## 8. Non-functional Requirements

- Mobile-first.
- Быстрое открытие и простой интерфейс.
- Минимум текста на ключевых экранах.
- Высокая прозрачность AI-рекомендаций.
- Защита чувствительных данных и геолокации.
- Возможность удалить профиль и историю.
- Отсутствие тёмных паттернов вовлечения.

## 9. Definition of Done для основной недели

Неделя считается успешной, если пользователь:

1. выбрал историю;
2. совершил связанное действие в реальном мире;
3. подтвердил результат;
4. оценил опыт как минимум нейтрально или положительно.
