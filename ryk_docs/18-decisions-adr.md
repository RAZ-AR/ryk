## ADR-001 — Клиент: Telegram Mini App

**Статус:** ✅ Accepted (2026-07-23)

**Контекст.** [MVP](10-mvp-scope.md) — быстрый тест weekly loop на 50–200 пользователях в одном городе, низкое трение установки, встроенные push.

**Решение.** Пилот — **Telegram Mini App**. Приглашения и мягкая ответственность (witness/buddy из [08-social](08-social-and-accountability.md)) естественно живут в мессенджере; push и идентификация «из коробки».

**Последствия.**
- Notification service — на Telegram push; mobile push позже.
- Геолокацию можно запрашивать через Telegram Mini App API.
- UI ограничен возможностями Mini App — учтено в [дизайн-системе](17-design-system.md).
- При подтверждённом retention (Phase 2+) — рассмотреть PWA/нативное (заведём superseding-ADR).

## ADR-002 — Стек: full-stack TypeScript (Next.js)

**Статус:** ✅ Accepted (2026-07-23) — разработка ведётся через Claude Code

**Контекст.** Продукт строится через Claude Code, соло/малой командой. Нужен минимум языков и максимум связности типов. На старте тяжёлого ML in-process нет — recommendation engine это «concierge вручную + LLM API» ([MVP](10-mvp-scope.md)).

**Решение.** **Один TypeScript-стек на Next.js**: Mini App (веб-приложение) + API routes как бэкенд. Prisma как ORM к PostgreSQL. AI Orchestrator — через LLM API с structured outputs.

**Причина.** Единый TS end-to-end (общие типы фронт↔бэк) максимально удобен для разработки через Claude Code; нет отдельного сервера на старте; легко деплоится на бесплатный тариф (ADR-003).

**Последствия.**
- Если recommendation platform вырастет в тяжёлый ML — вынесем отдельный сервис (Python/FastAPI) позже, отдельным ADR. Nest/standalone-сервер не берём преждевременно.
- `12-technical-architecture` компоненты (profile/wishlist/weekly/memory service) реализуются как модули внутри Next.js API, а не как отдельные сервисы.

## ADR-003 — Хостинг: бесплатный тариф (Vercel + Supabase)

**Статус:** ✅ Accepted (2026-07-23) — требование «для начала бесплатно»

**Контекст.** Нужен нулевой стартовый бюджет, staging + production, PostgreSQL.

**Решение.**
- **Приложение (Next.js Mini App + API):** **Vercel** free (Hobby) — preview-деплой на каждый PR ≈ staging, production по merge в `main`.
- **База + auth + storage:** **Supabase** free (PostgreSQL, 2 проекта — можно под staging и prod). Альтернатива под БД: **Neon** (serverless Postgres, free).
- **Секреты** — в Vercel Environment Variables (раздельно preview/production) и Supabase, не в коде.

**Причина.** $0 на старте, ноль администрирования сервера, отличная связка с Next.js и Claude Code.

**Последствия.**
- Модель окружений из плейбука (staging noindex + basic-auth) реализуется через Vercel preview + защиту preview-деплоя; отдельный VPS не нужен.
- **DigitalOcean дроплет** (исходный план плейбука) — это **Phase 2+**, когда важны контроль/стоимость на масштабе или long-running процессы. Тогда — superseding-ADR.

## ADR-005 — Аналитика: PostHog

**Статус:** ✅ Accepted (2026-07-23)

**Решение.** **PostHog** (облако, free tier): product analytics + воронка из 8 шагов + **feature flags** (полезны для experiment backlog из [11](11-analytics-and-kpis.md)) в одном. Amplitude — если понадобится зрелая аналитика на масштабе.

**Как реализовано (Фаза 10).**
- События отправляются **с сервера** (`posthog-node`) из server actions — там, где они реально происходят и уже провалидированы. Не зависит от блокировщиков и не расходится с тем, что записалось в БД.
- **Единый список событий** — `lib/analytics/events.ts`. Новое событие сначала туда: воронка из 8 шагов имеет смысл, только если названия не разъезжаются по коду.
- **Без ключа — тихий no-op.** Аналитика не может быть условием работы продукта.
- Свойство `environment` (`VERCEL_ENV`) разделяет прод и превью, чтобы тестовый трафик не пачкал воронку.
- ⚠️ **Приватность:** в свойствах событий **нет персональных данных** — ни текстов желаний, ни имён спутников и свидетелей, ни заметок из воспоминаний. Только категории, коды и счётчики. Это прямое следование «разделять чувствительные данные и продуктовую аналитику» из [12-technical-architecture](12-technical-architecture.md).
- Serverless: `flushAt: 1` + `await shutdown()` — функция Vercel может завершиться раньше фонового флаша.

## ADR-006 — Провайдеры данных

**Статус:** ✅ Accepted (2026-07-23) — старт на бесплатных/open-источниках + concierge

**Контекст.** Нужны погода, места/POI, события, карты/маршруты, геолокация. Пилотные города — **Белград, Нови-Сад, возможно Ереван** (Сербия и Армения). Требование — бесплатно на старте. В concierge-MVP часть данных собирается вручную ([10](10-mvp-scope.md)). Важно: для Балкан/Кавказа глобальные event-API неполны → **основной источник событий в пилоте — ручная локальная курация + местные тикет-сайты.**

**Рекомендация по категориям:**

| Категория | Основной (free) | Запасной / позже | Заметки по покрытию |
|---|---|---|---|
| **Погода** | **Open-Meteo** (free, без ключа, глобально) | OpenWeatherMap free | Отлично покрывает EU + Сербию + Армению |
| **Карты/тайлы** | **MapLibre + OSM** тайлы; **Mapbox** free (50k загрузок) | Google Maps (платно, позже) | OSM полон по Балканам и Кавказу |
| **Геокодинг** | **Nominatim (OSM)** free | Mapbox Geocoding | Соблюдать usage policy Nominatim |
| **Маршруты** | **OSRM** / **GraphHopper** (OSM) | Mapbox Directions | — |
| **Места / POI** | **OSM Overpass** (free) + **Foursquare Places** (free tier) | Google Places (платно, лучшие данные) | Overpass силён в EU/Сербии/Армении |
| **События** | **Ticketmaster Discovery API** (free) + **Eventbrite** (free) | PredictHQ (агрегатор, платно) | В EU сильно; в Сербии/Армении **тонко → concierge + локальные тикет-сайты** |
| **Музыка/концерты** | **Bandsintown** / **Songkick** | — | Дополняет Ticketmaster |
| **Геолокация** | Telegram Mini App location + браузерный Geolocation | — | С согласия пользователя ([12](12-technical-architecture.md)) |
| **Бронь ресторанов** | — (нет хорошего free API) | Google Reserve / локальные | В MVP — deep links + concierge |

**Решение.** MVP на **Open-Meteo + OSM (Overpass/Nominatim/MapLibre) + Ticketmaster/Eventbrite** как вспомогательных, а **основной источник событий для Белграда/Нови-Сада/Еревана — ручная локальная курация** (местные тикет-площадки и афиши) в рамках concierge-MVP.

**Реализация курации (Фаза 11).** Раздел `/concierge` — внутренний инструмент,
не часть продукта:

- **Доступ** — один общий токен `CONCIERGE_TOKEN` (env), отдельный от пользовательской
  сессии контур. Без токена раздел отдаёт 404: пустая админка приглашает её ломать.
  Аккаунтов и ролей нет — для пилота с одним-двумя кураторами их незачем заводить;
  когда кураторов станет больше, роли будут отдельным решением.
- **Снятие с показа** — поле `Experience.archivedAt`, не удаление: на впечатление
  ссылаются уже прожитые истории и воспоминания людей.
- **Отсев по дате** — событие с прошедшей датой перестаёт попадать в кандидаты
  автоматически. Впечатления без даты (прогулка, музей) живут всегда.
- **Язык** — интерфейс инструмента переведён наравне с продуктом (ADR-009).
  Раньше здесь стояло обратное решение — «русский и вне i18n, ради двух
  кураторов переводить незачем». Пересмотрено: кураторы сидят по разным
  городам пилота, и русский у них не обязательно первый. Здесь же куратор
  вводит en/es-текст карточки — форма, где половина полей на непонятном
  языке, ошибок только добавляет.
- **Отметка «спонсорское»** ставится куратором здесь и дальше всегда видна
  пользователю (обещание прозрачности, PRD §7).

## ADR-007 — Визуальное направление: хендофф «бумага + билет»

**Статус:** ✅ Accepted (2026-07-24) — заменяет черновую v0.1 дизайн-системы

**Контекст.** До появления дизайна визуальное направление было **черновиком**, собранным по двум Figma-референсам (Unicorn — пастельная «Aurora», soft-UI, объём; Sandow — структура). Затем появился готовый **hi-fi прототип** `design_handoff_ryk/` — 16 экранов с финальными цветами, типографикой и интерактивом. Прототип — источник правды по определению; черновик по референсам ему уступает.

**Решение.** Дизайн-система переписана на язык хендоффа ([17-design-system v0.2](17-design-system.md)).

**Что заменено:**

| Было (v0.1, черновик) | Стало (v0.2, хендофф) |
|---|---|
| Пастельные градиенты «Aurora» | Плоско, **без градиентов вообще** |
| Soft-UI, объём, мягкие тени | Бумажный принт, плоско; одна тень — на билете |
| brand `#6C5CE7` (индиго) | **`#F387C8` (розовый)** + бумага `#EBEAE7` |
| Скруглённые карточки (10–32px) | **Прямые углы по умолчанию (0)**, скругления точечные |
| Sora + Inter | **Golos Text · PT Serif · Cormorant · IBM Plex Mono · Caveat** |
| Обе темы (light + dark) | **Только светлая (paper)** — тёмной в хендоффе нет |
| Aurora hero | **Метафора билета** (отрывной корешок, перфорация, штрихкод) |

**Последствия.**
- ADR-001 (Telegram Mini App) и стек не меняются: прототип реализуем **своей кодовой базой** (Next.js + CSS Modules), а не копируя HTML прототипа.
- Область 390×844 из прототипа — эталон пропорций, а не фиксированный размер: в Mini App макет тянется.
- **Тёмная тема выпадает из MVP.** До появления её токенов `prefers-color-scheme` не переключает палитру. Это сознательное сужение Definition of Done по теме — зафиксировано в [CLAUDE.md](../CLAUDE.md).
- Навигация продукта уточнена хендоффом: dock из 4 разделов — **Неделя · Память · Желания · Баланс**. «Баланс» (Life Balance Model) получает экран уже в этом дизайне, хотя в [MVP-скоупе](10-mvp-scope.md) сложная life-analytics отложена → в MVP показываем простую версию.

**Осознанное отклонение от прототипа (контраст).** Прототип местами кладёт белый текст на розовый `#F387C8` (≈2:1) — это не проходит WCAG AA из нашего DoD. Решение: **на розовом использовать `ink #111`** (≈8:1; уже применяется в прототипе для дока и корешка) и `#B0468A` для мелкого розового текста на бумаге. Вид сохраняется, читаемость чинится — подробно в [17 §9](17-design-system.md).

## ADR-008 — AI-провайдер: Gemini (бесплатно) с фолбэком на Claude

**Статус:** ✅ Accepted (2026-07-25) — требование «пока без платного AI»

**Контекст.** Разбор желаний (Flow B) и будущие AI-функции требуют LLM со structured outputs. Claude точнее, но платный, а на этапе разработки и раннего пилота платить не хочется. При этом нельзя допустить, чтобы отсутствие ключа ломало продуктовый флоу.

**Варианты.**
- **Google Gemini Flash** — бесплатный tier без карты, structured outputs (`response_format` + JSON-схема), официальный SDK `@google/genai`. Лимитов бесплатного tier с запасом хватает: разбор желания — один короткий запрос.
- **Groq / OpenRouter free** — быстрее/дешевле, но JSON-режим слабее строгой схемы.
- **Только эвристика** — бесплатно и приватно, но качество разбора заметно ниже.

**Решение.** Цепочка провайдеров по наличию ключа, в порядке приоритета:

1. `GEMINI_API_KEY` → **Gemini Flash** (бесплатный tier) — путь по умолчанию.
2. `ANTHROPIC_API_KEY` → **Claude** — если нужен более точный разбор (платно).
3. Ключей нет → **эвристика** по ключевым словам.

Любой сбой провайдера (сеть, квота, кривой ответ) проваливается к следующему варианту — пользователь никогда не остаётся без результата.

**Последствия.**
- Провайдеры изолированы в `lib/ai/providers/*`, общая схема и нормализация — в `lib/ai/types.ts`. Добавить/заменить провайдера = один файл.
- Ответ модели считается **недоверенным вводом**: `normalizeWish` отбрасывает неизвестные категории и мусорные типы (покрыто юнит-тестами).
- ⚠️ **Приватность:** на бесплатных tier'ах провайдеры обычно оставляют право использовать данные для улучшения моделей. В приложение попадают личные желания пользователей — **перед пилотом проверить актуальную политику Google** и при необходимости перейти на платный tier или Claude. Связано с privacy-принципами [12-technical-architecture](12-technical-architecture.md).
- Претензия «AI как единственная платная позиция» из ADR-002/003 снимается: на старте платных позиций нет.

## ADR-009 — i18n: язык в cookie, контент каталога — в колонке `translations`

**Статус:** ✅ Accepted (2026-08-01)

**Контекст.** Языки en / ru / es решены давно, но «переводится всё» держится
на двух вещах, которые из кода неочевидны и оба раза были сделаны неверно.

**Решение 1 — источник языка в пределах запроса — cookie, а не БД.**
Язык живёт в двух местах, и роли у них разные:

- `ryk_locale` (cookie) — **единственный источник правды в запросе**. Её
  читает next-intl (`i18n/request.ts`), из неё же берут язык серверные
  компоненты через `getLocale()`.
- `users.locale` (БД) — для того, у чего запроса нет: крон подсказок и
  вебхук бота пишут человеку на его языке, не имея ни cookie, ни сессии.

Писать нужно **в оба места** — иначе получается ровно тот баг, из-за
которого решение и записано: сохранение профиля меняло только строку в БД,
и выбранный язык не доезжал до интерфейса до следующего входа в Mini App.
Все преобразования локали и запись cookie собраны в `lib/i18n/locale.ts`
и `lib/i18n/localeCookie.ts` — не размазывать их обратно.

**Решение 2 — контент каталога переводится в БД, колонкой `translations`.**
Карточки впечатлений — это данные, а не строки интерфейса, и в `messages/*.json`
им не место: их заводит куратор, а не разработчик. Базовый язык — русский, он
лежит в самих колонках `title` / `description` / `location`; остальные языки —
в JSONB `experiences.translations` вида `{ "en": {…}, "es": {…} }`.

- **Откат поштучный:** нет языка или отдельного поля — берётся базовый текст.
  Пустая карточка хуже карточки на чужом языке: без заголовка человек просто
  не сможет выбрать неделю.
- **Перевод у куратора необязателен** — событие надо успеть завести, пока оно
  не прошло; текст дописывается следующим заходом.
- **У курируемого каталога перевод обязателен** и проверяется тестом
  (`prisma/catalogI18n.test.ts`), а не типом: slug'и лежат обычными строками,
  литерального union из них нет. Забыть перевод у новой карточки нельзя.
- **Город (`experiences.city`) не переводится намеренно:** по нему идёт подбор
  «рядом» через совпадение с `users.city`, и перевод сломал бы сравнение.
  Пользователю город впечатления не показывается — только место.

**Последствия.**
- Общие примитивы (`Dock`, `Ticket`) не имеют текстовых дефолтов: подписи —
  обязательные пропы. Зашитая по-русски строка внутри примитива пролезает
  в чужой язык молча, и заметить это, правя только экран, нечем.
- Числа форматируются через `formatNumber`/`intlTag` (`lib/i18n/locale.ts`),
  не через жёсткий `toLocaleString("ru-RU")`.
- Для Intl взят **en-GB**, а не en-US: пилот европейский — день впереди
  месяца, 24 часа. Даты на билете остаются в формате `ДД.ММ` во всех языках:
  это часть визуальной метафоры ([ADR-007](#adr-007--визуальное-направление-хендофф-бумага--билет)).
- Названия мест в en/es даются сербской латиницей, а не переводятся: так их
  подпишет карта и поймёт таксист. Переводится только то, что действительно
  описание («Двориште Кинотеке» → «двор Синематеки»), а не имя собственное.

## ADR-010 — Навигация: три времени вместо пяти разделов

**Статус:** ✅ Accepted (2026-08-04)

**Контекст.** Док был на пять целей: `Неделя · Память · ◉ лента · Желания · Год`.
Три из них — настоящие разделы, две — нет:

- **Центральная кнопка вела в дубль.** `DiscoverSection` и лента на главной
  показывали одну и ту же `deck` с одними и теми же «интересно / не интересно».
  Отличалась только подача: колода по одной против вертикального списка. На
  вопрос «чем центр отличается от ленты, которая уже на главной», ответа не было.
- **«Год» — не раздел, а сводка.** Read-only агрегат тех же воспоминаний, что
  лежат в «Памяти», — то же содержимое с другого расстояния.

Диапазон 3–5 пунктов рабочий сам по себе, но пять берут, когда пять миров
реально есть. У Ryk ядро — **одно решение в неделю**, а навигация была
устроена как у контентного приложения с пятью равноправными мирами.

**Решение.** Док перечисляет **времена, а не экраны**: `Сейчас · Хочу · Было`.

| Пункт | Что внутри |
|---|---|
| **Сейчас** (`now`) | карусель предстоящего, блок недели, лента идей |
| **Хочу** (`wish`) | вишлист |
| **Было** (`past`) | архив-плёнка и сводка года над ней |

Колода и полный недельный цикл остаются как есть, но **оверлеями** с тех
экранов, которым принадлежат: колода — по ссылке «По одной →» в строке
заголовка ленты, недельный цикл — по тапу на блок недели. Вершиной навигации
им быть незачем.

**О знаках (уточнено 2026-08-04).** Изначально решение было «иконок в доке
нет»: при трёх пунктах пиктограмма ничего не ускоряет, а неоднозначный знак
требует подписи — и получается два элемента вместо одного. Возражение снято
не отменой аргумента, а сменой паттерна: подпись показывает **только
активный** пункт, а неактивные несут знак. Слово и знак нигде не дублируют
друг друга, ни один пункт не остаётся немым — у того, где ты находишься,
подпись есть всегда.

Знаки берут смысл из продукта, а не из общей иконографики: «Сейчас» — билет,
пробитый компостером; «Хочу» — звезда, которой в продукте помечают
сохранённое; «Было» — силуэт билета с вырезами, то есть твои корешки.

Побочно это чинит и цель нажатия: неактивный пункт стал 44×44 вместо
прежних 59×37.

**Последствия.**
- `DockSection = "now" | "wish" | "past"`; `DockTarget` и `discoverLabel`
  больше нет, центральная кнопка со знаком удалена вместе со стилями.
- `YearSection` удалён, его роль забрал `YearSummary` — свёрнутая строка
  над плёнкой архива. Свёрнуто по умолчанию: развёрнутый отчёт при каждом
  входе превращает архив в счёт ([banned patterns](17-design-system.md)).
- Медиазапрос дока под узкие экраны не нужен: три пилюли по три-пять букв
  занимают 215px из 320. Пять пунктов со знаком приходилось ужимать до 9px.
- Резерв под док `--ryk-screen-bottom-dock` 104 → 92px (высота дока 60 → 53px).
- `Button` получил вариант `link` — то же текстовое действие, что `ghost`, но
  по содержимому: блочная кнопка разорвала бы строку заголовка раздела.
- Заголовок экрана остался «Память», хотя пункт называется «Было»: навигация
  говорит о времени, экран — о содержании, и «Память» здесь сильнее.
- **Риск:** «Год» и колода ушли на второй уровень, их будут открывать реже.
  Если PostHog покажет, что за годом ходили часто, строку в «Было» можно
  раскрывать по умолчанию — это одна строка, откат структуры не нужен.

## ADR-011 — Срок желания: три горизонта, один фокус

**Статус:** ✅ Accepted (2026-08-04)

**Контекст.** Из вишлиста нельзя было ничего сделать: желания копились, но
пути «прожить» у них не было. Просьба звучала как «назначить любому желанию
день, неделю или месяц и отмечать сделанным» — то есть, буквально, как
планировщик задач. Это упирается сразу в два принципа: постулат №2 «одна
неделя — одна история» и anti-reference №1 «не productivity-дашборд / todo»
([17-design-system](17-design-system.md)).

**Решение.** Горизонта три, и **точность растёт по мере приближения**:

| Горизонт | Где живёт | Сколько желаний |
|---|---|---|
| «Когда-нибудь» | `Wish.status = SOMEDAY` | сколько угодно |
| «В этом месяце» | `Wish.status = THIS_MONTH` | сколько угодно |
| «На этой неделе» + день | `weekly_story` (`wishId`, `plannedFor`) | **ровно одно** |

Дальний горизонт — свойство желания, ближний — свойство недели. Поэтому
назначить конкретный день можно только одному желанию: оно и становится
историей недели, то есть тем самым единственным фокусом.

**Ограничение держит схема, а не интерфейс.** У `weekly_story` уникальный
ключ `(userId, weekStart)`, и обойти его нельзя ни второй вкладкой, ни
гонкой запросов. Интерфейс лишь объясняет отказ.

**Занятую неделю не подменяем молча.** `selectStory` в этом случае тихо
возвращает `ok` — для ленты это уместно, там человек видит выбранную
историю перед собой. В вишлисте он смотрит в список желаний и о неделе не
думает: подменить её без спроса значило бы отменить его же выбор. Поэтому
у `scheduleWish` есть отдельный ответ `week_taken` с названием занявшей
истории, а замена — только по явному согласию.

**«Сделано» — два разных действия, а не одно.**
- Желание стало историей недели → ведём в существующий чек-ин: там
  появляется воспоминание, оценка и, при желании, фото. Второй путь к тому
  же итогу нам не нужен.
- Желание прожито мимо цикла → `Wish.status = REALIZED`. Оно остаётся в
  списке зачёркнутым, с рукописной пометкой «случилось»: прятать прожитое
  значит приравнять радость к удалению.

**Дни показываем только оставшиеся.** Прошедшие дни недели не выводятся
вовсе — выключенный понедельник в списке читается как «ты его упустил»,
а продукт устроен так, чтобы упрёков не делать (постулат №4).

**Последствия.**
- Миграции не потребовалось: `WishStatus` уже знал `SOMEDAY / THIS_MONTH /
  SOON / REALIZED`, а `weekly_story` — `plannedFor` и связь `wishId`.
- Новые события аналитики: `wish_scheduled` (с горизонтом) и
  `wish_realized`. Первое — главный сигнал: если `thisWeek` почти не
  встречается, список копится, но в прожитое не превращается, а это и есть
  провал продукта.
- Календарь и дашборд на главной **не делаются** — обсуждались и отложены
  до того, как станет видно, доходят ли желания до недели вообще.

## Чек-лист аккаунтов и ключей (для поднятия MVP)

Значения ключей пользователь заводит сам; в репо — только `.env.example` с именами ([CLAUDE.md](../CLAUDE.md)).

**Нужно сейчас — всё бесплатно, кроме LLM:**
- **GitHub** — репозиторий (уже есть).
- **Vercel** — подключить к GitHub (app + preview/prod). Free.
- **Supabase** — проект в **регионе EU** (Postgres + auth + storage). Free.
- **Telegram @BotFather** — создать бота и Mini App (токен бота). Free.
- **PostHog** — проект аналитики (EU-облако). Free.
- **Google Gemini** — ключ для разбора желаний, **бесплатный tier** ([AI Studio](https://aistudio.google.com/apikey)). См. ADR-008.
- **Anthropic Claude** — опционально и платно, если понадобится более точный разбор (ADR-008). Без него всё работает.

**Провайдеры данных (по мере надобности):**
- **Open-Meteo** — погода, **ключ не нужен**.
- **OSM Nominatim / Overpass** — геокодинг/POI, **ключ не нужен** (соблюдать usage policy; на масштабе — self-host или платный геокодер).
- **Mapbox** — опционально, если нужны красивые тайлы/геокодинг: бесплатный токен (50k загрузок/мес).
- **Ticketmaster Discovery API** — бесплатный ключ (события в EU).
- **Eventbrite** — API-ключ. ⚠️ публичный поиск чужих событий у них ограничен — полезен в основном для своих/партнёрских событий, не как главный discovery.
- **Bandsintown / Songkick** — доступ по запросу (концерты), позже.

**Опционально:** свой домен (Mini App работает и на URL Vercel; кастомный домен — по желанию).
