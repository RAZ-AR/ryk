# User Flows

## Flow A: Первый запуск

Как устроено в коде сейчас (`components/onboarding/OnboardingFlow.tsx`). Док
скрыт на всех шагах; почти каждый шаг можно пропустить — назвать что-то о себе
право, а не обязанность.

Все шаги после обложки лежат на живом фоне (`OnboardingBackdrop`): пятна
фольги плывут, сдвигаются наклоном телефона и перетекают на новое место с
каждым шагом. Кнопки шага — в доке, прижатом к низу экрана: главное действие
всегда под пальцем, даже на длинных шагах.

1. **Обложка** (`welcome`) — обещание «Одна история каждую неделю». Ссылка «У меня
   уже есть профиль» ведёт через место (шаг 2) сразу к рамкам (шаг 9).
2. **Где ты** (`place`) — первый вопрос, потому что от города зависит всё:
   афиша, погода, праздники, валюта цен. Пилотные города плитками с
   названием страны и «Другой город» с полем. Город по IP (заголовки Vercel,
   `lib/geo/ipCity.ts`) уже отмечен с пометкой «похоже, ты здесь», но не
   сохраняется без «Дальше». «Определить по геопозиции» — только по нажатию:
   датчик Telegram (Bot API 8.0), иначе геолокация браузера
   (`lib/telegram/location.ts`); дальше 60 км от пилотного города — открываем
   «Другой город». «Позже» — без города.
3. **Вдохновение** (`inspire`) — «Радость не измеряется размером»: 8 мини-билетов
   с маленькими радостями и вопрос «Что из этого про тебя?». Выбранное →
   `joyTraits`. Без номера шага и счётчика; можно ничего не выбрать.
4. **Категории** (`categories`) — что интересно; «Назад» — к вдохновению.
5. **Свайпы** (`swipe`) — конкретные идеи «да / нет», цена в валюте города
   (динары или драмы). «Назад» возвращает к предыдущей идее и снимает её
   ответ; с первой идеи — к категориям.
6. **Хороший момент** (`moment`) — «когда последний раз было хорошо» своими
   словами (≤500). Текст хранится как есть, из него же читаются черты
   (`traitsFromText`) — дополняют выбранное на шаге 3.
7. **Что откладывается** (`postponed`) — свободный текст.
8. **Ритм** (`rhythm`) — главный барьер (повторный тап снимает) и свободные окна.
9. **Рамки** (`params`) — имя («как к тебе обращаться», подставлено из
   Telegram), бюджет в валюте города, формат, новизна. «Назад» — на ритм или
   на место, смотря откуда пришли. Ошибка сохранения видна, а не немая.
10. **Первый «Лист дня».** Отдельного финального экрана нет: после сохранения
   открывается главная, и первым на ней стоит лист дня с данными нового
   человека, под ним — одноразовая строка «а историю недели выберем вместе» со
   ссылкой в недельный цикл (`lib/ui/freshWelcome.ts`). Неделю не торопим:
   первую историю человек выбирает, когда сам откроет блок недели (Flow C).

## Flow «День»: лист дня

Каждый день, вне зависимости от состояния недели ([ADR-015](18-decisions-adr.md)).

1. Человек открывает «Сейчас» — первым видит «Лист дня»: число, день недели ·
   город · страна, день года, небо и свет, одну маленькую радость, «Скоро»
   (до двух строк: праздник пилотной страны, сезон или событие каталога).
2. Радость только читается: нечего отмечать, нечего пропустить. В тот же день
   она та же при любой перезагрузке, завтра — другая.
3. Ниже — обычная главная: что впереди, блок недели, лента. Лист никуда не
   ведёт и ничего не требует.
4. Сменил город в профиле — лист следует за ним: дата по поясу города,
   праздники его страны.

## Flow B: Добавление желания

1. Нажать «Добавить желание».
2. Ввести текст, голос или ссылку.
3. AI структурирует желание.
4. Пользователь подтверждает категорию, примерный бюджет и период.
5. Желание попадает в wishlist.
6. Система сообщает, когда появится хороший момент для реализации.

## Flow C: Выбор истории недели

1. В начале недели пользователь видит 3–5 карточек.
2. Каждая карточка содержит:
   - идею;
   - причину рекомендации;
   - цену;
   - длительность;
   - расстояние;
   - уровень новизны;
   - доступные даты.
3. Пользователь выбирает одну карточку.
4. При необходимости отвечает на один уточняющий вопрос.
5. Система формирует план.

## Flow D: Приглашение друга

1. Пользователь выбирает «Пойти с кем-то».
2. Ryk предлагает подходящих контактов или создаёт ссылку-приглашение.
3. Пользователь отправляет короткое сообщение.
4. Друг подтверждает или отклоняет.
5. При отказе система предлагает другого человека либо solo-версию.

## Flow E: Мягкая ответственность

1. Пользователь выбирает «Добавить свидетеля».
2. Друг получает только краткое обещание и дедлайн.
3. В конце недели друг видит «получилось» или «перенесено».
4. Нет публичных рейтингов и наказаний.

## Flow F: Срыв плана

1. Система замечает риск: нет билета, испортилась погода, пользователь откладывает.
2. AI спрашивает о барьере.
3. Предлагает:
   - упростить;
   - перенести в рамках недели;
   - заменить;
   - выполнить rescue mission.
4. Пользователь выбирает один вариант.
5. Неделя остаётся активной.

## Flow G: Завершение

1. После события приходит ненавязчивый check-in.
2. Пользователь нажимает «Сделано».
3. Выбирает эмоцию.
4. Добавляет фото или фразу.
5. Memory сохраняется.
6. AI задаёт только один полезный вопрос для улучшения рекомендаций.

## Flow H: «Выбери за меня»

1. Пользователь включает режим спонтанности.
2. Система выбирает один вариант из допустимого диапазона.
3. Показывает краткое объяснение и кнопку отказа.
4. После подтверждения начинается обычный weekly flow.

## Flow I: Пара

1. Два пользователя связывают профили.
2. Система находит пересечение интересов.
3. Раз в неделю предлагает 3 совместных идеи.
4. Каждый голосует независимо.
5. Выигрывает пересечение или компромиссный вариант.
6. Совместная история появляется у обоих.
