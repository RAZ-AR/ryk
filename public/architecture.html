Одна история в неделю — и весь код, который это обслуживает

Монолит на Next.js App Router: один процесс отдаёт и UI, и API. Клиента-SPA нет — экраны собираются на сервере (RSC), мутации идут через server actions. Всё, что снаружи, подключено так, чтобы его отсутствие не ломало продукт: нет ключа AI — работает эвристика, нет PostHog — тихий no-op, нет Storage — просто нет кнопки фото.

Дерево читается сверху вниз как приоритет: сначала согласие человека, потом польза сообщения, и только в конце — частота. Порядок проверок в коде такой же, и менять его нельзя: если сперва считать лимит, выключивший уведомления начнёт тратить квоту молчанием.

04

Четыре независимых контура доступа

Пользователь lib/auth/*

Клиент шлёт initData → POST /api/auth → HMAC-проверка по схеме Telegram (secret = HMAC("WebAppData", bot_token), сравнение в постоянном времени) → upsert по telegramId → подписанный JWT (jose, HS256, 30 дней) в httpOnly-cookie ryk_session.

dev-вход {dev:true} → пользователь dev-local, жёстко заблокирован при NODE_ENV=production
возврат после удаления аккаунта: deletedAt сбрасывается вместе со всем профилем — иначе вечный экран входа
Куратор
cookie ryk_concierge
Один общий CONCIERGE_TOKEN, 12 часов, подписан тем же SESSION_SECRET. Нет токена → раздела не существует (404), а не «пустая админка».
Cron
Bearer CRON_SECRET
Заголовок ставит Vercel Cron. Сравнение timingSafeEqual, минимум 16 символов, иначе отказ.
Вебхук бота
x-telegram-bot-api-secret-token
Telegram не подписывает вебхуки HMAC — секрет задаётся при setWebhook и сверяется побайтно.

Пятый рубеж — на уровне БД: миграция enable_rls включает Row Level Security на всех таблицах и не заводит ни одной политики. Авто-REST Supabase с anon-ключом не прочитает ничего; Prisma ходит владельцем (BYPASSRLS).

weekly.ts 406 строк — ядро
Скоринг Relevance × Feasibility × Timing + портфель с разнообразием категорий. Каждая рекомендация несёт WhyCode (LIKED_CATEGORY · IN_BUDGET · NEARBY · CURATED · FRESH) — объяснение обязательно по PRD §7.
barrierBoost: NO_TIME → ≤60 мин ×1.6 · TOO_EXPENSIVE → цена 0 ×1.6 · NO_ENERGY → RITUAL ×1.6
MAX_EVENT_CANDIDATES = 1 — остальные места за вызовами и ритуалами
mix.ts пропорция ленты
Событий не больше EVENT_SHARE = 0.25, иначе лента скатывается в афишу города. Перемешивание детерминированное: mulberry32 + FNV-хеш от userId + дата — карточки не прыгают между рендерами и проверяемы тестом.
недостача одного типа добирается другим: пустая лента хуже ленты без событий
nudges.ts + nudgeDelivery.ts самое опасное место
Движок возвращает код, не текст — тон живёт в messages/*. Отправлять разрешено только WEATHER_SWAP · TOMORROW · INVITE_SOMEONE.
молчат всегда: ON_TRACK (ничего не просит) · WEATHER_WATCH (тревога без действия) · TODAY (уже поздно, читается как давление)
потолок MAX_NUDGES_PER_WEEK = 2, повтор кода за неделю запрещён
rescue.ts спасение недели
Барьер задаёт, что считать «меньше»: WEATHER → под крышу (CULTURE/JOY/REST/CONNECTION), NO_ENERGY → ≤90 мин, TOO_EXPENSIVE → бесплатное. Ни один путь не помечает неделю провалом — DEFERRED это нормальный исход.
year.ts сознательно НЕ радар с целями: пустые категории не рисуются, процентов нет — счётчики стыда запрещены

liveExperiences.ts — общее условие «что вообще можно показывать»: не архивировано куратором и дата не в прошлом. Вынесено отдельно, чтобы лента и недельные кандидаты не разъехались.

Фоновые процессы

Ежедневный крон vercel.json · 0 8 * * *

Собирает контекст (история недели + прогноз + отправленное на этой неделе), строит buildNudge, спрашивает разрешение у decideDelivery, шлёт через Bot API и записывает в interventions. Повторный запуск в тот же день ничего не отправит второй раз — идемпотентность обеспечена журналом, а не таймером.

Инварианты — что нельзя сломать незаметно

Данные
  • Одна история на (userId, weekStart) — уникальный индекс, не проверка в коде
  • Впечатления не удаляются, а архивируются: на них ссылаются прошлые истории
  • Удаление аккаунта стирает зависимые записи явно, строка User остаётся
Тон и давление
  • Не больше 2 сообщений в неделю, три кода из шести молчат всегда
  • Тексты подсказок — в messages/*, движок отдаёт только коды
  • DEFERRED — валидный исход недели, нигде не считается провалом
Приватность
  • В свойствах аналитики нет текстов желаний, имён и заметок
  • Бакет фото приватный: наружу только подписанная ссылка на час
  • RLS без политик — anon-ключ Supabase не видит таблиц
Деградация
  • AI → Gemini → Claude → эвристика; пользователь всегда получает результат
  • Погода, аналитика, Storage — тихо выключаются, а не бросают
  • Server action проверяет сессию сам, независимо от рендера страницы
Из журнала уроков проекта, оба про верстку, но оба — про архитектурную привычку: флекс с overflow:auto требует min-height:0 у себя же (иначе dock уезжает за экран на длинном контенте), и принадлежность действия к карточке держится структурой, а не отступом (кнопки реакций — третья полоса билета, а не блок под ним).
