## Контекст проекта

**Ryk** — персональный AI-компаньон по жизненному опыту. Помогает человеку не
откладывать жизнь и проживать **одно настоящее впечатление каждую неделю**.

- Обещание: **Every week deserves one story** / «Одна настоящая история каждую неделю».
- North Star: **Meaningful Weeks** — недели, где пользователь создал и сохранил лично значимое воспоминание.
- Основной цикл: `Understand → Discover → Commit → Experience → Remember → Learn`.
- Продукт хорош, когда пользователь **закрывает приложение и идёт жить**. Оптимизируем не screen time, а реальные completion events.

## Продуктовые постулаты (не нарушать без явного решения)

1. **Воспоминание, а не задача.** Единица продукта — experience → memory, не task.
2. **Одна неделя — одна история.** Один фокус вместо бесконечного списка.
3. **Помощь важнее напоминаний.** Push слаб; полезны время, компания, маршрут, билеты.
4. **Мягкое обязательство, без давления.** Rescue mission вместо «ты провалил неделю».
5. **Прозрачность AI.** У каждой рекомендации есть объяснение «почему это подходит»; спонсорское явно маркируется.
6. **Пользователь владеет данными.** AI-память видна, редактируема, удаляема; экспорт и удаление профиля обязательны.

## Правила работы агента

1. **План перед делом.** Для нетривиального (3+ действия, архитектурный выбор) — сначала короткий план, дождись «ок».
2. **Жди ответов на ❓.** Не выдумывай ответы за пользователя.
3. **Verify before done.** Показывай результат (вывод, скриншот, зелёный workflow, curl 200). Никаких «должно работать».
4. **Никогда не коммить в `main` напрямую.** Только ветка + PR.
5. **Секреты руками не трогаем.** Токены/ключи/пароли добавляет пользователь сам (GitHub Secrets / `.env` на сервере). Агент их не печатает в чат, не коммитит, не кладёт в код. В репо — только `.env.example` с пустыми ключами; реальные `.env` в `.gitignore`.
6. **Платное и необратимое — только с подтверждением.** Дроплеты, домены, покупки, удаление данных, публикация. Показывай, что создаётся и сколько стоит.
7. **grep перед удалением.** Перед удалением/переименованием роутов и файлов — `grep` по `.github/`, тестам и конфигам: путь может быть захардкожен в CI/smoke-тесте.
8. **Дизайн-система строго.** Сначала [токены](ryk_docs/17-design-system.md) и примитивы, потом UI. Никаких hex-литералов и самопальных кнопок-`<span>`.
9. **Skills actually fire.** При UI-работе — вызывай релевантный дизайн-скилл в начале и объявляй его; не цитируй правила по памяти.
10. **Фиксируй урок.** После каждой правки-коррекции от человека — добавляй запись в раздел «Lessons» ниже, чтобы не повторять.

## Definition of Done

### Продуктовая неделя (из [PRD](ryk_docs/04-product-prd.md))
Пользователь: выбрал историю → совершил действие в реальном мире → подтвердил результат → оценил ≥ нейтрально.

### Инженерная задача / UI
- Прогнаны тесты и сборка (зелёные), живой curl/скриншот показан.
- UI проверен на **375 / 768 / 1280** px. Тема — **только светлая (paper)**: тёмной в хендоффе нет, отложена ([ADR-007](ryk_docs/18-decisions-adr.md)).
- Нет хардкод-токенов (grep по hex в компонентах — пусто), нет call-site оверрайдов примитивов.
- Доступность: контраст, targets, `prefers-reduced-motion` (см. [17-design-system](ryk_docs/17-design-system.md)).
- Нет тёмных паттернов вовлечения (streaks, счётчики стыда, обратный отсчёт-давление) — см. [banned patterns](ryk_docs/17-design-system.md).
- Копия проходит правила тона [14-brand-and-copy](ryk_docs/14-brand-and-copy.md) (нет запрещённых формулировок).

- **Данные:** Open-Meteo + OSM + Ticketmaster (Eventbrite ограничен) + concierge (ADR-006).

## Lessons (append-only)

> Формат записи: **Правило** — что случилось / точная коррекция / как применять в следующий раз.

**Флекс-контейнер с `overflow: auto` требует `min-height: 0` у себя же.** В `AppShell`
`.content { flex: 1; overflow-y: auto }` без `min-height: 0` не скроллился сам — вместо
этого рос `.shell` (был `min-height: 100vh`, не фиксированная высота), и `dock`
(`position: absolute` относительно `.shell`) на длинном контенте уезжал за пределы
экрана в Telegram Mini App. Пользователь заметил на реальном контенте («dock идёт
ниже видимой части экрана»), в коротких моках на dev-данных баг не проявлялся.
Исправлено: `.shell` — фиксированная `100dvh` / `var(--tg-viewport-stable-height)`,
`.content` — `min-height: 0`, `dock` — `position: fixed` с учётом
`--tg-safe-area-inset-bottom`. **Как применять:** для любого экрана с плавающим
элементом поверх скролла — проверять на контенте выше одного экрана, не только
на первом моке; при `flex: 1; overflow: auto` всегда добавлять `min-height: 0` рядом.

**Принадлежность действия к карточке держится структурой, а не отступом.** В ленте
реакции «Интересно / Не интересно» лежали отдельным блоком под билетом через
`gap: 12px`, и тень была только у белой части. В потоке одинаковых карточек пара
кнопок читалась как начало следующего билета, а не как действие над предыдущим:
расстояние до «своего» билета и до «чужого» отличалось некритично. Пользователь
заметил на реальной ленте, на одиночном моке проблема не видна. Исправлено:
действия стали третьей полосой билета за второй линией перфорации, тень переехала
с `.top` на `.ticket` целиком. **Как применять:** если элемент относится к карточке —
он внутри карточки; сближать отступом бесполезно, в вертикальном потоке
одинаковых блоков близость не читается. Заодно: `<button>` нельзя оборачивать
вокруг карточки с `<h2>` и `<div>` внутри — зона нажатия делается накладкой
`position: absolute; inset: 0`, иначе кнопки действий оказываются внутри кнопки.
